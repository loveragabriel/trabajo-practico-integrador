# Seguimiento de la versión de entrega

Esta versión parte de `68d4bab`, que incorporó la reorganización del módulo de paseos. Usamos el PR de entrega para que el equipo pueda comparar y repetir la prueba antes de integrar.

| Bloque de ClickUp o checklist | Qué está listo en la versión | Qué queda por hacer |
| --- | --- | --- |
| Autenticación, usuarios y paseadores | Registro, ingreso, perfil propio, edición de cobertura y consulta de otro paseador con sesión. | El equipo puede cerrar las tarjetas una vez revisado su alcance. |
| Mascotas, paseos y agenda | Alta y edición de mascotas, publicación, búsqueda por barrio, agenda e historial del paseador, cancelación y estados. | Revisión de las pantallas y de las consignas del tutor. |
| Reservas y cupos | Reserva por mascota, historial del cliente, cancelación, reactivación y prueba concurrente con PostgreSQL. | Repetir el recorrido en la instancia pública una vez disponible. |
| Reseñas | Reseña única por dueño participante, comentario, promedio y cantidad en el perfil del paseador. | Revisar el texto que se mostrará en la demo. |
| Pruebas y contratos de API | Swagger, contrato de operaciones, verificación de los dos roles y prueba de último cupo. | Confirmar el resultado de CI en GitHub al subir la rama. |
| Informe y README | Informe PDF con capturas, instalación, demo y guía de despliegue. | Revisar el PDF entre los tres e incorporar los enlaces definitivos. |
| Despliegue y video | Imagen de aplicación preparada y guion de la demostración. | Publicar frontend/API y PostgreSQL, grabar el video y comprobar los enlaces. |

Las marcas corresponden a esta versión. El estado de las tarjetas se confirma en ClickUp antes de cerrar cada una.
